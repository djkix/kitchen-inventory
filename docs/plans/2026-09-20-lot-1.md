# Lot 1 — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Livrer le lot 1 du cahier des charges (inventaire : auth, emplacements, produits, stock, scan, reconnaissance, DLC, recherche, écrans mobiles) dans un monorepo publié sur GitHub avec image Docker sur GHCR.

**Architecture:** Monorepo npm workspaces. `packages/shared` porte les schémas Zod, les unités et les règles métier pures (section 15). `apps/api` (NestJS + Prisma) expose `/api/v1` et sert le front compilé. `apps/web` (React + Vite PWA) est l'interface mobile. Une seule image Docker, trois services compose.

**Tech Stack:** Node 22, TypeScript 5.9 strict, NestJS 12, Prisma 6, PostgreSQL 16 (`pg_trgm`), Zod 3, Vitest 4, React 19, Vite 7, Tailwind 4, React Router 7, TanStack Query 5, `zxing-wasm`, `vite-plugin-pwa`, `@node-rs/argon2`, `nestjs-pino`.

**Spec:** `docs/cahier-des-charges.md` (normatif) et `docs/decisions/2026-09-20-choix-implementation-lot-1.md` (choix laissés au jugement).

## Global Constraints

- `StockItem.quantity` est matérialisée : toute écriture insère un `StockMovement` puis recalcule `quantity = Σ delta` dans la même transaction. Jamais d'écriture directe.
- Chaque opération d'écriture sur le stock accepte `clientOpId` (unique) ; un identifiant déjà vu renvoie le résultat précédent (idempotence).
- Règles de la section 15 dans `packages/shared/src/rules`, fonctions pures testées, couverture ≥ 80 %.
- Anglais pour le code, français pour les libellés et les messages d'erreur.
- TypeScript `strict`, `any` interdit hors tests.
- Validation par Zod, schémas définis dans `packages/shared`, réutilisés côté front.
- Aucun changement de schéma sans migration Prisma commitée.
- Aucun test ne touche le réseau : Open Food Facts et vision rejoués depuis `apps/api/test/fixtures`.
- Toutes les routes exigent une session sauf `POST /auth/login`, `POST /auth/setup`, `GET /auth/status`, `GET /health`.
- Erreurs : `{error: {code, message, details?}}` avec les codes de la section 16.
- Pagination : `{items, total, page, limit}`, `limit` défaut 50, max 200.
- Unités autorisées : PIECE, GRAM, KILOGRAM, MILLILITER, LITER, PACK, BOX, SACHET. Conversions g↔kg et ml↔l seulement.
- Commits Conventional Commits avec référence EF quand elle existe.
